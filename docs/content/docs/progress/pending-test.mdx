# Pending Tests

- Image task resume across refresh: start generating an image through an async-capable relay (e.g. xinfeng) and refresh the page while the node is still spinning. After reopening the canvas the node should stay in its generating state, keep polling, and finish with the image in place — no "generation interrupted" message. Refresh again after completion and the image should still be there. If the task was deleted on the relay side, the node should show the real error (not "interrupted"), and regenerate recovers it.

- Chain shots: split an image into 3+ frames with the 9-grid split (enable "arrange as storyboard"), select them all and click "Chain shots" in the floating toolbar. It should report "Shots chained: N shots, N-1 new connections" and draw connections in 1→2→3 order. Clicking again should say they are already chained. If one selected shot already has a downstream generation node, that segment must stay untouched.

- Delivery package: on a canvas with 2–3 shots and at least one "image → text" connection, open the top-left menu → "Export delivery package". A zip should download containing `shots.csv` (opens in Excel without garbled text; index, in/out time, kind, file, line, prompt), `shots.json`, `voiceover.txt`, `subtitles.srt`, `materials/` and a readme. Shot order and durations should match the CapCut draft; only "image → text" connections count as lines, while "text → image" prompt connections must not leak into the voice-over script. Drop `subtitles.srt` into CapCut or a player — subtitles should line up with the shots. If shots have lines but the canvas has no audio at all, an extra prompt should ask you to record voice-over. Exporting an empty canvas should say there is nothing to deliver.

- CapCut draft export: on a canvas with 2–3 images and one video, open the top-left menu → "Export CapCut draft". A zip should download. After extracting, the "Canvas Cut" folder should contain `draft_content.json`, `draft_meta_info.json`, a `materials/` folder and a readme. Copy the whole folder into CapCut's draft directory and open CapCut — the project should appear, with shots ordered like the canvas (connections first, otherwise left-to-right and top-to-bottom), each image 3 seconds, videos keeping their real length, no gaps or overlaps, and generated audio on its own audio track. A canvas dominated by portrait media should export a portrait draft. Exporting an empty canvas should say there is nothing to export instead of downloading an empty package.

- Large images: generate an image through a channel that returns the original 20 MB+ file (or drop such a file onto the canvas). The node should show the image once generation finishes instead of "Generation was interrupted by a page refresh." Zooming the node should stay sharp (the full-size image is kept, not just the thumbnail), and the image should still be there after reloading the page and be downloadable.
- Refresh during large-image save: generate a large image and reload immediately. If "The image was generated, but the page refreshed while the large file was still being saved" appears, the save really was cut off — regenerating is enough. Otherwise the image should just appear with no red text.

- Subject library: on a generated character image, click "Save subject" in the node toolbar and pick "Character". The asset panel should then show a "Subject" group at the top containing it. Clicking the subject inserts an image node and auto-connects it to the node currently being edited, with a toast confirming the reference. The same subject should be available on every canvas. It should also appear on the assets page with preview and export support.

- Subject consistency: attach a character subject to an image node and write only the action (e.g. "she pushes the door open into the rain"). The result should keep the subject's face and outfit, and the outgoing prompt should contain the "locked subjects must stay identical" paragraph. Without any subject attached, that paragraph must not appear.

- Angle matrix: on an image node, open "Multi-angle" and switch the top mode from "Single" to "3x3 grid". The preview should turn into a 3x3 thumbnail grid that reacts to camera distance and wide angle. "Generate 9 angles" should produce nine differently oriented images on the right of the source node, then group them into a group named "Angle matrix · 9 angles" whose frame hugs the actual image sizes; the group should drag as a whole. "Three views" and "12 angles" should produce 3 and 12 images. The single-angle mode must behave exactly as before.

- Character turnaround plugin: create a "Character Turnaround" node from the plugin panel, describe the character, and click generate. It should return a single sheet showing front, side and back views of the same character. "Four views" and "Expression grid" should return four angles and a 3x3 expression sheet. When an upstream character image is connected, the sheet should keep that character's likeness. The "copy to canvas" toolbar action should turn the sheet into a standalone image node usable as a reference.

- Story push plugin: enter one scene, pick "Story four frames", and run it. The result should be a table with shot size, time point,画面 content, camera movement and an English prompt per frame, with consistent character description across frames. "Before / after" should return the three-second-before, current and three-second-after frames; "Shot flow" should return a medium establishing shot, a close-up and a detail shot.

- Shot teardown plugin: provide a playable mp4/webm URL (or connect a video node upstream), choose the frame count and run. It should extract frames in the browser and output a frame-by-frame table, a structural breakdown and a replication storyboard. A text model without vision support should produce a clear notice rather than an empty result. Cross-origin videos that cannot be read should report a load failure.

- Plugin multi-image analysis: requires a vision-capable text model. If the configured channel model cannot read images, the teardown should report that the model returned no content, which is a channel limitation rather than a plugin defect.

The current release needs manual verification in these areas:

- Drag alignment and automatic arranging: while dragging one node or a multi-selection, the node must snap to another node's left edge, center, or right edge (and the same vertically), showing a thin guide line at the snapped position, and the drop position must match the drag preview exactly. Hold Alt while dragging to disable snapping for free placement. With two or more nodes selected, the floating selection toolbar and the node context menu must offer "Tidy grid" and "Tidy flow": grid arranging lays the selected nodes out in a tidy grid keeping the current top-to-bottom, left-to-right order; flow arranging layers them left to right following the connections (stacking each layer vertically), and falls back to grid arranging when nothing in the selection is connected. When a group node is involved, the group box and its children move together as one piece. The result must be undoable.

- Asynchronous image generation (long-running models such as Midjourney): generate a model that takes minutes (for example Midjourney v8.2) through a relay that supports `Prefer: respond-async` (for example xinfeng.best). The request must carry `Prefer: respond-async`. When the relay answers 202, the canvas must take the task id immediately, poll `GET /v1/images/tasks/{id}` every 3 seconds, and fetch the image from `GET /v1/images/tasks/{id}/result` once the task finishes — instead of failing because the gateway cut the connection at around 75 seconds. Both text-to-image and reference-image editing must behave this way. Relays that do not support the header (they ignore it and return the image directly) must behave exactly as before. If a relay answers 202 but has no task endpoint, the app must report "中转接受了异步生图请求，但任务查询接口不可用（404）".

- OpenAI-compatible Midjourney request parameters and four-image results: when `2k` + `21:9` is selected (UI dimensions `2688×1152`), the request must send `aspect_ratio: "21:9"` and `hd: true`; it must not reduce the ratio to `7:3` or send `hd: false`. Prompt `--ar` must not override the UI selection; `--hd=true`, `--s250`, `--c`, and `--raw` must be converted into structured API fields instead of left in prompt text. Selecting 4K must produce a clear local unsupported message for the current MJ channel, never silently downgrade to 1K/2K. Requests must use MJ-specific numeric quality and URL response parameters instead of generic pixel-size/base64 options. When the upstream returns `image_urls` / `imageUrls` as an array or JSON-encoded array, the canvas must show all independent images and prefer that list without also adding a fallback grid image. Verify both text-to-image and reference-image edits.

- Gateway error pages: generate an image, video, or audio through a relay that answers with an HTML error page (nginx or Cloudflare 502/503). The node must show a message such as "网关错误（502），接口服务暂时不可用，请稍后重试" instead of pasting a block of HTML. When the local proxy cannot reach the upstream, it must show "The local proxy could not reach the upstream endpoint (the connection was refused or interrupted)…" instead of the raw `fetch failed`. Other HTML pages without a status code keep the existing truncated preview.

- Upstream closed the connection with no response: generate with a relay whose synchronous image call gets cut by its gateway (for example a Midjourney-style model that keeps the upstream waiting, with a gateway read timeout around 75 seconds). The node must show "The upstream closed the connection before returning anything (usually a relay gateway timeout…)" and explain that the result may have been generated upstream but cannot be retrieved, instead of a generic timeout or "All images failed to generate". Plain network failures, auth failures, and rate limits must keep their own existing messages.

- Upstream generated an image but the canvas reports failure: generate with an asynchronous relay (for example a Midjourney-style endpoint that only returns a task ID) and the image should appear on the canvas instead of "All images failed to generate". Responses that carry the image under non-standard fields such as `output`, `artifacts`, `imageUrl`, `imageUrls`, or a nested `data.data` must also be recognized. When a remote image URL cannot be fetched (CORS or a non-2xx response), the app should fall back to loading it with an image tag. When generation genuinely fails, the node must show the upstream's own error message rather than a generic "All images failed to generate".

- Image URL persistence: canvas and image-workbench generation should download each remote API result only once, validate it as a decodable image, and persist it in IndexedDB; `200` responses containing non-image data should fail, stopping canvas generation during download should not save or apply the result, CORS-blocked but displayable images should keep their original URL without an empty storage key, and plugin calls should still receive Data URLs whenever the remote image is readable.

- Agent message metadata: image attachments, Skills, canvas references, and local previews should survive page refreshes and Agent restarts through exact `clientMessageId`, `threadId`, and `turnId` ownership; protocol upgrades must not reset the independent storage format, unknown or damaged storage must refuse writes without overwriting files, no records may be silently pruned by count or size, and deleting a thread should remove its metadata and preview assets without relying on browser IndexedDB or text matching.
- Prompt Center layout, source synchronization, search, asset insertion, prompt detail dialogs, and compact split-layout prompt pickers in the image and video workbenches.
- Workbench history image cleanup: after generating content in the image or video workbench, deleting an asset, canvas image node, canvas content, or canvas project must not remove thumbnails, results, or references from generation history; deleting a generation record should still remove its dedicated local files.
- Prompt text labels: when a regular node or generation configuration is connected to several text nodes, every upstream text block appended to the prompt should start with its label such as `【Text 1】` or `【Text 2】`, numbered in connection order and matching both the `@` references in the prompt and the reference bar. - Local storage settings: the Settings page should provide a Local storage tab that reads only the `vs-studio` database and shows IndexedDB usage, total site usage, browser quota, quota percentage, and per-object-store record counts and content size; refreshing after local data changes should update the figures without blocking the rest of the page.

## 图片分辨率尺寸表

选择分辨率和宽高比后，W/H 按下表填写，单位为像素。预设尺寸不受「16 倍数对齐」开关影响；该开关只控制手动输入尺寸时的对齐。最终生成尺寸以所选模型的实际输出为准。

| 宽高比 | 1K | 2K | 4K |
| --- | ---: | ---: | ---: |
| **1:1** | **1024 × 1024** | **2048 × 2048** | **2880 × 2880** |
| **2:3** | 1024 × 1536 | 1360 × 2048 | 2336 × 3520 |
| **3:2** | 1536 × 1024 | 2048 × 1360 | 3520 × 2336 |
| **4:3** | 1024 × 768 | 2048 × 1536 | 3312 × 2480 |
| **3:4** | 768 × 1024 | 1536 × 2048 | 2480 × 3312 |
| **16:9** | 1536 × 864 | 2048 × 1152 | **3840 × 2160** |
| **9:16** | 864 × 1536 | 1152 × 2048 | **2160 × 3840** |
| **21:9** | 2016 × 864 | 2688 × 1152 | **3840 × 1648** |
| **9:21** | 864 × 2016 | 1152 × 2688 | **1648 × 3840** |

待验收：

- 在画布和图像工作台逐项切换 3 档分辨率与 9 种比例，W/H 应与表格一致，重新打开设置后仍选中正确档位；重点检查 1K 的 2:3、16:9、21:9 及对应竖图，以及 4K 的 1:1。
- 所有 4K 预设提交时均不应触发本地总像素或最长边限制；生成和编辑请求、调用脚本应收到所选像素尺寸。
- 分辨率为自动时保留比例选择，比例为自动时禁用 W/H；手动输入 W/H 后，对齐开关仍应按原有方式工作。
- Gemini 请求应带 aspectRatio（所选比例）；分辨率选了 1K / 2K / 4K 时应按尺寸表带上 imageConfig.imageSize，选自动时不带。质量不参与分辨率换算，视频尺寸设置保持原有行为。
- 图像质量可选自动与 5 档（低 / 中 / 高 / 极高 / 最高），请求里的 quality 字段应与所选档位一致，且尺寸不随质量变化。
