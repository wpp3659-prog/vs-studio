# 竞品调研与取长补短路线

本文是一次完整的竞品调研记录：用 **REA（Reverse Engineer Anything）** 逆向本地安装的 MiniMax Design，再横向拆解 LibTV、OiiOii、小云雀，最后落到「我们该做什么、先做什么」。

> 说明：竞品功能会随版本快速变化，本文结论以调研当时抓到的安装包与公开资料为准；具体参数以用户实际打开时为准。

## 一、调研方法与证据来源

| 来源 | 手段 | 拿到的证据 |
| --- | --- | --- |
| MiniMax Design 43.7.5（本地安装） | REA 6.5.0 `analyze-javascript-application` 静态分析 app.asar | 4972 个模块节点、6080 条关系边、135 个 bridge API、918 个源文件；解包核心 bundle 读真实界面文案与数据结构 |
| LibTV | 官网 + 百科产品功能页 | 无限画布 + 节点工作流、20+ AI 能力清单、Skill Hub |
| OiiOii | 官方访谈 + 2.0 升级报道 | 7 个专家 Agent、拉片复刻 18 维度、智能画布、Skill 库 |
| 小云雀 | 官网功能卡 + 10 家画布横评 | 3D 导演台、智能预演、ScriptBird、重制转绘 |
| 横向对照 | 10 家 AI 视频画布功能横评 | 「6 项标配」与「5 项重点能力」的分布 |

REA 的用法很直接：把 asar 交给它，它输出的是**带证据的代码结构**，而不是截图猜测。

```bash
npx rea-agents setup
rea analyze-javascript-application "F:/MiniMax Design/current/resources/app.asar" --json > rea.json
```

## 二、MiniMax Design 逆向结论（代码级证据）

### 2.1 产品结构

- 版本 **43.7.5**，Electron 应用，内部代号 **hilo**（项目目录 `.hilo/`，MCP 工具名 `hilo_workspace*`）。
- 只有三个真实业务页面：`CanvasPage`（无限画布）、`ChatPage`（对话）、`EditorInterface`（时间线编辑器）。其余 300+ 个 bundle 是代码高亮语言包，属于干扰项。
- 项目以本地文件夹形式存储：`.hilo/canvas.json` + `.hilo/index.sqlite` + 同目录素材文件。

### 2.2 画布数据模型

`canvas.json` 结构极简：

```json
{ "version": 1, "mode": "workflow", "nodes": [], "edges": [], "hiddenAssetIds": [] }
```

- 节点类型只有 **file / image / video / audio / text / table / group**，没有「分镜节点」「角色节点」这类业务节点。
- 节点带 `assetId` 与 `parentId`；分组成组靠 `group-xxxx` 节点 + `parentId`。
- 边只有一种类型：`derivation`（派生）。**没有「参考」「首帧」「尾帧」的语义区分**，语义靠节点内 `data` 字段表达。
- 一个 69 节点的真实模板里，分组多达 16 个——**它靠「组」来做分镜段落管理**。

结论：它的画布是**素材画板 + 派生素材关系**，不是工作流引擎。真正的「生成编排」不写在画布里。

### 2.3 编辑能力（时间线）

`EditorInterface` 是一个完整的非编时间线，界面文案里能读到的能力：

- 轨道编辑：分割、修剪、复制、删除、吸附、标记、定格、调整图层、复合素材。
- 音频：降噪（多档预设 + 学习噪声配置）、音量闪避（人声触发 BGM 降低）、静音检测与移除。
- 速度曲线：全程逐步加速、中段快速加速、平滑慢动作、高潮戏剧性减速等预设。
- **导出到剪映**：把时间线转成剪映草稿格式，写入本地并自动打开剪映。文案原文：「正在写入草稿，请勿关闭编辑器」「未检测到剪映，草稿包已导出到画布」。
- 导出到画布 / 导出本地（PNG/JPG/WEBP、WAV）。

这是它最被低估的部分：**画布负责生成，时间线负责成片**，中间用「导出到剪映」打通专业剪辑生态。

### 2.4 生成与资产链路

- 模型：`MiniMax-H3` / `minimax-h3-max` / `minimax-h3-max-turbo`、`doubao-seedream-5-0-pro`、`gpt-image-2`、`midjourney-8.2`、`kling-avatar`。
- 计费粒度极细：图片按张、TTS 按字符（HD / Turbo 两档）、音乐按次与按分钟、文字按百万 token、`storyboard` 单独计价，**每个结果都能退积分**（「已退还 {{count}} 积分」「积分退还处理中」）。
- 生成参数强约束：`min/max_duration_ms`、`total_max_duration_ms`、`min/max_aspect_ratio`、`max_images_with_video`、`max_video_audio_refs`、`exclusive_groups`。**这些是模型能力矩阵**，用于在 UI 上禁用不支持的组合。

### 2.5 图片工具集（画布内右键）

宫格切分（自定义行列、多宫格生成）、**创建分镜组**（切分后一键成组）、高清放大（2K 超分，附加增强描述）、图层拆分、重打光（多种影调预设：王家卫迷幻、银翼杀手、沙丘救赎、奥本海默灰等）、去掉字幕（`erase-subtitle`）、生成字幕（`asr`）、调色（色温/背景）、全景图（进入全景模式、拖拽视角、截取当前视角）、裁剪、构图参考线、批注、OCR 取字。

**要点：图片工具是「加工 + 拆解 + 成组」三件套，全部围绕「把一个多宫格图变成可用的分镜资产」。**

### 2.6 版本与协作细节

- 文本节点有完整版本历史：上一个/下一个版本、与当前对比、恢复此版本、还原前自动保存（「已还原，还原前的内容已存为新版本」）。
- 有冲突解决机制（「需要处理的冲突」「请先处理完所有冲突再退出」），说明它做过多人/多端编辑。

### 3.2 各家真正的杀手锏

**LibTV —— 后期工具箱最完整。**
定位是「专业影视后期」：逐帧拉片、片段重拍、人声背景分离，300+ 专业音色，@ 与连线两种引用方式都支持。
它的 20 项独家功能里，最值得抄的是 **多机位 9/25 宫格、剧情推演 4 宫格、画面推演（3 秒后 / 5 秒前）**——这三个都是「用一张图推演出下一组镜头」，直接减少抽卡次数。

**OiiOii —— 把「看别人的片子」变成生产力。**
核心竞争力是**拉片复刻**：上传一条视频，从最多 18 个专业维度（景别、运镜、叙事结构、节奏、色彩等）拆解，再替换角色/场景/道具，一键生成结构相同内容全新的视频。
第二个是**智能画布**：素材和 Agent 对话框打通，用大白话改画面（「把背景换成下雨的街道」）。
第三个是 **Skill 库**：把「世界杯热点」「萌宠科普」「电商展示」这类内容固化成工作流，选好就直接出片。
另有 **7 个专家 Agent**（艺术总监、角色总监、分镜总监、音乐总监等），各管一段。

**小云雀 —— 3D 预演 + 连载工业化。**
它的独门是**智能预演**：让智能体先把整组镜头的走位排好再生成，从源头减少抽卡——横评里专业影视向超创的原话是「3D 白模是我使用画布最重要的功能之一」。
第二是**连载模式**：日更泡面番等 4 种连载模式 + 批量补图，专为系列化生产设计。
第三是 **ScriptBird 剧本模型 + 六维评测**（剧本内容、开篇亮点、主线架构、节奏把控、角色塑造、剧本可用率）。
第四是**重制转绘**：18 地区 / 100 分钟整片复刻，白模继承机位运镜切镜。

**MiniMax Design —— 生成之后的「成片能力」。**
它没有角色库、没有拉片、没有 3D 预演，但它是四家里唯一把**非编时间线**和**剪映草稿导出**做完整的。降噪、音量闪避、速度曲线这些都是真正的成片工序。
换句话说：别人在卷「怎么生成得更准」，它在卷「生成完怎么剪成能交的片子」。

### 3.3 行业共识：6 项标配

横评确认，以下 6 项已经是所有画布平台的标配，缺一项就掉队：

1. 资产引用生成（含 `@资产名`）
2. 近期引用自动找回
3. 浏览器内编辑器
4. 导出到外部专业编辑器
5. 基础视频生成能力
6. 素材/资产管理

**对照我们：第 1、2、3、5、6 都有，第 4 完全没有（没有导出到剪映）。**

## 四、差距分析：我们缺什么

按「对成片质量的影响 × 实现代价」排序。

### P0：直接影响成片，且我们有基础能接

| 缺口 | 竞品怎么做 | 我们的优势 | 建议落点 |
| --- | --- | --- | --- |
| **角色/场景资产库（主体库）** | 角色三视图、多角度、可复用资产，改设定图全项目同步 | 已有 `@引用` 链路与节点系统 | 新插件 `asset-library`：三视图生成 + 设定卡 + 全项目引用 |
| **多机位 / 多角度一致性** | 9/25 宫格、360 度角度呈现 | 已有「多角度」对话框 | 升级为「角度矩阵」：一次出 9 视图并自动成组 |
| **剧情推演 / 画面推演** | 4 宫格剧情推演、3 秒后 / 5 秒前 | 已有分镜表与镜头卡 | 新插件 `story-push`：四格推演 + 前后画面推演 |
| **宫格 → 分镜组** | 切分后一键成组，不消耗积分 | 已有切分对话框 | 加「创建分镜组」按钮，把切分结果直接排成流程 |

### P1：决定「能不能交片」

| 缺口 | 竞品怎么做 | 建议落点 |
| --- | --- | --- |
| **导出到剪映** | MiniMax Design 写草稿包 | 生成剪映草稿 JSON（`draft_content.json`），把画布镜头按顺序排到时间线 |
| **音画处理** | 降噪、人声分离、音量闪避 | 先做「人声/BGM 分离提示 + 音量闪避建议」的文本侧，音频处理留待后续 |
| **成片时间线** | MiniMax Design 完整非编 | 短期不做完整非编，用「分镜序列 → 一键出片清单 + 剪映草稿」替代 |

### P2：差异化，但依赖较重

| 缺口 | 竞品怎么做 | 判断 |
| --- | --- | --- |
| **拉片复刻（逐帧拆解）** | OiiOii 18 维度、LibTV 逐帧 + 片段重拍 | **高价值**。我们有视觉模型能力，可做「上传视频 → 多维度拆解 → 生成同结构分镜表」，是我们最能做出差异的一项 |
| **3D 白模预演** | 小云雀 3D 导演台 | **代价高**（需要 3D 场景与机位系统）。先用「2D 机位示意 + 空间描述」的轻量替代，不碰真 3D |
| **多人协作** | LibTV 团队版、20 子账号 | 我们本地优先，短期不做实时协作，优先做「项目导出/导入」撑协作 |
| **批量出海 / 多语种** | OiiOii 多版本分支 | 中期可做「同分镜多语种配音与字幕批量生成」 |

## 五、升级路线

### 第一阶段：把「生成得更准」补上（P0）

1. **`asset-library` 角色/场景资产库插件**：三视图（正面/侧面/背面）+ 表情九宫格 + 设定卡；节点作为「主体」被其它节点 `@` 引用，保证跨镜头一致。
2. **角度矩阵**：把现有「多角度」升级为 3×3 九视图，一次出图并自动成组。
3. **`story-push` 剧情推演插件**：四格剧情推演（起承转合）+ 画面推演（3 秒后 / 5 秒前）。
4. **宫格 → 分镜组**：切分对话框加「创建分镜组」，把同一次多宫格结果直接变成分镜序列。

### 第二阶段：把「能交片」补上（P1）

5. **导出剪映草稿**：分镜序列 → 剪映 `draft_content.json`，按镜头顺序、时长、转场排好，用户在剪映里继续精剪。
6. **成片清单**：一键输出「镜头表 + 素材文件 + 配音稿 + 字幕」的交付包。

### 第三阶段：做差异化（P2）

7. **拉片复刻插件**：上传参考视频 → 多维度拆解（景别/运镜/节奏/色彩/光线/叙事结构）→ 输出同结构分镜表 + 每镜英文提示词。
8. **Skill 工作流市场**：把「短剧预告」「电商展示」「萌宠日常」这类成品工作流打包成一键套用的插件组合。

## 六、明确不做的事

- **不做完整非编时间线**：我们的定位是画布生成，剪辑交给剪映/达芬奇。把生成做准比把剪辑做全更值。
- **不做真 3D 白模**：代价与收益不匹配，先用 2D 机位示意替代。
- **不做实时多人协作**：本地优先架构下不划算，先用项目导入导出覆盖协作。
- **不做模型渠道绑定**：继续保持任意 OpenAI 兼容接口可接，这是相对竞品的结构优势。

## 七、一句话结论

> 竞品分三条路线：LibTV 卷后期、OiiOii 卷拉片与 Skill、小云雀卷 3D 预演与连载工业化、MiniMax Design 卷成片时间线。
> **我们最该补的是「角色资产库 + 多角度一致性 + 剧情推演」这三件事**——它们直接决定多镜头片子里人物会不会串脸；
> 其次是「导出剪映」，因为它把画布从「素材生成器」变成「能交片的工具」。

## 八、第二轮复核：线上界面级证据（REA CDP）

上面几节的能力清单主要来自安装包逆向与公开资料。第二轮补了一次**线上界面级**核对：用 REA 6.5.0 的 CDP 观察能力直接读三家网页端**已渲染的界面**，看真实的功能命名与信息架构，而不是看宣传文案。

### 8.1 方法

| 手段 | REA 命令 | 用途 |
| --- | --- | --- |
| 页面结构 | `rea inspect-web-page` | 可访问性树 = 界面上的全部按钮与标签名；顺带拿 DOM、脚本清单、存储键名 |
| 前端产物 | `rea analyze-web-bundle` | 脚本分块、路由与接口候选 |
| 视觉证据 | `rea capture-web-screenshot` | 首屏截图，核对信息架构 |
| 桌面端 | `rea analyze-javascript-application` | 本地网关 bundle 的模块与依赖关系 |

抓取用**独立 Chrome 配置 + 独立用户目录**，不驱动点击、不注入脚本（REA 的 CDP 观察是只读的），因此结论不受「脚本模拟出来的假界面」干扰。

### 8.2 三家网页端的真实信息架构

**LibTV**（侧栏原文）：`首页 / 项目 / 资产 / 插件 / 创作 / LibTV 画布 / LibTV Agent(BETA) / 社区 / 创作者挑战赛 / 学院`。
特色功能入口：`3D-BOX`、`剧本原创与改编`、`导演执导`、`角色造型室`、`视频生成`、`图片生成`、`音频生成`、`剧本生成`、`智能剪辑`。
创作精选频道：`全网爆款 / 王者大赛 / 精选画布 / 专业影视 / 短剧漫剧 / 商业广告 / 动漫游戏 / 教育生活 / TV工具箱`。
作品卡片直接挂「可一键复制」——**社区作品能还原成画布再改**，这是它区别于普通作品广场的地方。

**OiiOii**：7 个岗位化 Agent（艺术总监 / 编剧 / 角色设计师 / 场景设计师 / 产品设计师 / 分镜师 / 音乐总监），每个都有 IP 形象。用户感知到的不是模型能力，而是**分工**。

**小云雀**：顶部 `最新活动 / 创作工具 / 创意营销 / 模型生态 / 会员套餐 / 使用教程`；主能力 5 项（视频生成 / 图片生成 / 短剧 Agent / 营销 Agent / 爆款复刻）；创意工具 8 项（剧情广告 / 三视图生成 / 达人带货 / 提示词提取 / 分镜脚本编写 / 品牌大片 / 知识类视频生成 / 字幕擦除）。
关键差异：**首页中央是「一句话输入框 + 技能 + 模型选择 + 偏好设置」，画布不是起点**；案例卡片上有「查看工作流」，即**案例 = 可复用工作流**。

**MiniMax Design**（本地 4.0.1 网关 `dist/main.js`，REA 静态重建）：21.3 MB 源码、**1,861 个模块**、**5,870 条模块依赖边**、2,345,997 个 AST 节点。它把画布当工作台、资产中心当长期记忆，两者用 SQLite 解耦（资产血缘、10 秒软删除撤销、文本版本按 hash 寻址、插件节点 KV 独立存储）。

### 8.3 复核结论：共同点是「中间物」

四家都在做同一件事——把创作拆成**可交付的中间物**：剧本 → 分镜表 → 镜头卡 → 素材 → 成片。用户每一步都能看见、能改、能回退。

我们已经有画布、Agent、插件、多模型中转，零件齐了，**缺的是零件之间的结构化中间层**。上一轮的路线补了「生成得更准」（角色资产、角度矩阵、剧情推演）与「能交片」（剪映草稿、交付包），但**从剧本到分镜这一跳仍然要靠 Agent 逐条建节点**：一场 12 个镜头的戏，就是 12 次建卡 + 12 次建配置 + 24 条连线，调用次数多、容易错位。

### 8.4 本轮落地：分镜编排原语

新增 Agent 工具 `canvas_create_storyboard`，一次调用把一场戏铺到画布：

- 输入：`title / style / aspect / shots[]`（镜号、景别、运镜、时长、画面、台词、提示词），可带生成参数（模型、尺寸、张数）。
- 产出：1 个「场次设定」文本节点（全局风格与画幅）+ 每个镜头 1 张分镜卡 + 1 个图片生成配置节点，按列网格排布，自动连线「设定 → 配置」「分镜卡 → 配置」。
- `autoRun` 默认关闭：先把分镜铺出来让用户确认，再决定要不要批量出图——避免一次误触把整场戏都扣费。

这样「剧本 → 分镜 → 出图」在画布上是**一次工具调用 + 一次确认**，和竞品「短剧 Agent」「分镜师」的体感对齐，同时保留我们「每一步都可见可改」的优势。

### 8.5 本轮落地：画布模板（一键同款）

LibTV 的作品卡片挂「可一键复制」、小云雀与 OiiOii 都有「爆款复刻」、MiniMax 有广场工作流——本质都是**把别人（或自己过去）的结构直接搬过来再改**。

我们补的是最基础的那一层：画布上选中一段（节点 + 内部连线，含分组）→「存为模板」→ 在任意画布「铺到画布」。两个刻意的取舍：

- **只存结构与提示词，不存图片/视频本体**。模板是「怎么搭」，不是「搭出来什么」。这样模板库不会把本地存储撑爆，也避免把别人的成片素材当成自己的资产。
- **铺开时全部换新 id**，连线与分组引用同步重写。否则同一张画布铺两次会出现 id 冲突，连线指向错节点。

竞品那层「社区作品 → 一键复制」还需要内容供给，属于运营侧；我们把机制先备好。
