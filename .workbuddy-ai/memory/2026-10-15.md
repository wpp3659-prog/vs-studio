### 6. 隔离方案调研（用户否决了「改写 config.toml」）

- 我提的方案 A「程序自动改写 `~/.codex/config.toml` 里那 3 行」被**用户明确否决**：

- 改用方案②（隔离配置）。**已核实 codex 提供两种隔离机制**：
  1. `CODEX_HOME` 环境变量（`Layer $CODEX_HOME/<name>.config.toml`）
  2. `-c/--config <key=value>`（dotted path，**`app-server` 子命令也支持**）
  3. 另有 `-p/--profile`（= `$CODEX_HOME/<name>.config.toml` 叠加）
- 结论：给画布 Agent 单独一份 `CODEX_HOME` 在技术上成立，可做到**完全不碰用户的 `~/.codex/config.toml`**。
- 相关源码定位：
  - `canvas-agent/src/config.ts` —— `CONFIG_DIR = ~/.infinite-canvas`、`CONFIG_FILE = canvas-agent.json`、
    `loadConfig/saveConfig/ensureSiteWorkspace`。**新增 agent 专用 codex 配置目录的自然落点。**

## 新增「一键启动.bat」+ 三个 bat 统一为 BOM+CRLF

用户问「以后启动是不是两个 bat 都要点」。原来确实是两个（画布网页 + Agent），
答完后顺手做了**一键启动**，降低操作成本。

- 新增根目录 **`一键启动.bat`**：先检查 `web\node_modules` 和 `canvas-agent\node_modules`
  （缺则自动 `npm install`），再用 `start "标题" cmd /k call "%~dp0启动.bat"` 开两个独立窗口，
  最后提示「本窗口可关」。
- **保留了单独的 `启动.bat` / `启动Agent-本地版.bat`**（单独调试时用，一键启动内部也是调它们）。

**⚠️ 关键坑：我写的 bat 是 LF 换行 + 无 BOM，中文会乱码 / cmd 可能解析异常。**
项目里原有的 `启动.bat` 是 **BOM + CRLF**。修复方式（Python）：
```python
b=open(p,'rb').read()
if b.startswith(b'\xef\xbb\xbf'): b=b[3:]
txt=b.decode('utf-8').replace('\r\n','\n').replace('\r','\n')
open(p,'wb').write(b'\xef\xbb\xbf'+'\r\n'.join(txt.split('\n')).encode('utf-8'))
```
**以后写这个项目的 .bat 一律要 BOM + CRLF**，用 Write 工具写完记得规范化。

**start 行正确写法**：`start "窗口标题" cmd /k call "%~dp0脚本.bat"`。
（曾试过 `cmd /k ""%~dp0脚本.bat""` 双层引号，也能用但嵌套更绕，最终选 `cmd /k call` 更稳。）

**⚠️ 沙箱限制**：在 WorkBuddy 沙箱里**无法验证 `start` 开新窗口**——
`cmd //c` 包装会立刻返回、`Start-Process cmd.exe` 被安全策略拦截、

## Agent 模型下拉「列表不全」= HTTP 304 缓存问题（已修）

**用户报的现象**：Agent 前端界面模型下拉只有 `GPT-5.6-Sol` / `GPT-5.5` / `GPT-5.4`，
缺 `GPT-5.6-Terra`、`GPT-5.6-Luna`，而且 `GPT-5.4` 本该是 hidden 却被显示了。

**排查结论：不是数据源问题，是 HTTP 缓存层。**
- 起独立脚本直连 `/agent/codex/models`，实返**完整 5 条**：
  `gpt-5.6-sol / gpt-5.6-terra / gpt-5.6-luna / gpt-5.5 / gpt-5.2`。
- Agent 日志里该接口一直是 **`status=304`** —— 铁证。
- Express 默认开 **ETag**（`W/"150a-..."`），且路由**没设 `Cache-Control`**。
- 前端 `fetchAgentJson` 用裸 `fetch(url)`（无 `cache: "no-store"`），
  拿到 304 → `res.json()` 失败 catch 成 `{}` → `data` 为空 → `if (!models.length) return;` **静默丢弃刷新** → 界面停在更早那份列表。
- 所以截图里的 `GPT-5.4` 根本不在当前返回里，是**旧响应缓存**。

**顺带排除的伪因**（都验证过，不是问题）：
- `~/.codex/model_catalog.json`（11 条，含 gpt-6-*）—— 没在 config.toml 里声明 `model_catalog_json`，不参与；复制进 agent home 也不影响。
- `minimal_client_version` —— terra/luna 要 0.144.0，实际 0.146.0，够。
- 前端过滤逻辑（`AGENT_REASONING_EFFORTS` / `codex-auto-review` / `displayName` 去重）—— 干净，5 条全过。

**修复（两处）**：
1. `canvas-agent/src/server/http.ts`：`app.disable("etag")` + 全局中间件 `res.setHeader("Cache-Control", "no-store")`。
   ⚠️ 注意 `app.get("/health")` 和 `/config` 在免鉴权段、注册顺序在这层中间件之前——
   实际中间件插在 `express.json` 之后、**所有路由之前**，覆盖全部接口。
2. `web/src/services/api/canvas-agent.ts` 的 `fetchAgentJson`：`fetch(url, { cache: "no-store", ...init })`。
3. 防御：`local-agent-panel.tsx` 里 `if (!models.length) return;` 改成带日志的 `addEventLog`，
   避免同类问题再表现成「没反应」。

**验证**：起临时实例（PORT=17399）实测 → `ETag: null`、`Cache-Control: no-store`、
条件请求回 **200** 且 body 5384 字节 → 修复成立。`npm test` 131 pass / 0 fail。

**⚠️ 关键教训（通用）**：`res.ok` 对 304 是 `true`，`if (!res.ok) throw` **拦不住 304**。
自建 HTTP 服务的接口一律要 `no-store`，否则浏览器条件缓存会让「刷新」变成静默无操作。
已把整条排查流程沉淀成 skill：`http-304-stale-list-diagnosis`。
